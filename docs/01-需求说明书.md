## 1. 项目背景与定位

### 1.1 一句话定位
一款**轻量级个人运动轨迹记录**微信小程序，用腾讯地图实时记录徒步、散步、跑步等运动的轨迹与运动数据，支持地图打点、轨迹回看、导出轨迹图分享。

**技术形态**：前后端分离——微信小程序 + 自建 Node.js 后端（Fastify + MongoDB），文件存储阿里云 OSS。

### 1.2 要解决的问题
- 记录"今天走了哪条路、多远、多久、配速如何"
- 在轨迹上标记有意义的事件（打卡点、休息点、拍照点），留住"时间+地点"的记忆
- 把运动成果以一张好看的轨迹图分享出去

### 1.3 目标用户
- 18~50 岁、有日常步行/跑步/轻户外习惯的微信用户
- 不需要 Keep 类重型社区，只想要"记录 + 分享"的轻工具

### 1.4 明确不做（第一版）
- 不做社交社区（关注/点赞/挑战赛/线上马拉松）——运营重，只保留"薄社交"（分享）
- 不做课程、训练计划、商城、硬件联动
- 不做骑行/登山等扩展运动类型（架构上预留类型扩展）
- 不做 3D 轨迹 / Flyover 飞越、AR 导航等重功能
- 不做防作弊系统 / 专业训练分析（功率、TSS 等）
- 不做 H5 分享落地页、微信运动同步（预留接口）

> 取舍依据见竞品分析：docs/02-竞品分析.md

## 3. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 轨迹点 ≤ 5000 点时地图流畅；列表分页加载；页面首屏 < 2s |
| 功耗 | 定位节流（位置未变不重复采点）、后台降低采样频率、页面退出停止定位 |
| 兼容 | 基础库 ≥ 2.19.0；覆盖 iOS/Android 主流机型；真机验证后台定位 |
| 隐私 | 轨迹为敏感数据：本地存储为主；如用云端需明示隐私政策；位置权限拒绝时的降级体验 |
| 可用性 | 单手操作、大按钮；记录页保持屏幕常亮（`wx.setKeepScreenOn`） |
| 可靠性 | 记录中断恢复提示；关键操作二次确认（结束/删除） |

## 4. 技术选型

| 层 | 选型 | 说明 |
|---|---|---|
| 前端框架 | 微信小程序原生 + JavaScript | 轻量项目，不引入 Taro/uni-app，避免跨端复杂度 |
| UI | **tdesign-miniprogram**（TDesign 小程序组件库） | 通过 npm 安装，按需引入；主题定制用 CSS 变量 |
| 地图 | 微信 `map` 组件 + **腾讯位置服务 QQMapWX SDK** | 内置地图组件天然支持 `polyline`/`marker`；QQMapWX 用于逆地理编码、POI 搜索 |
| 定位 | `wx.startLocationUpdate` / `wx.startLocationUpdateBackground` + `isHighAccuracy` | 后台持续定位 + 位置变化监听；高精度模式采集海拔 |
| 后端框架 | **Node.js + Fastify + Mongoose** | 性能好、自带 schema 校验；Mongoose 管理 MongoDB |
| 数据库 | **MongoDB**（新建独立库） | 本地开发与线上已有实例，直接新建库使用，不容器化 MongoDB |
| 对象存储 | **阿里云 OSS**（STS 临时密钥直传） | 打点照片、头像、导出图；后端签发 STS 凭证，小程序直传，后端只存 URL |
| 鉴权 | **JWT**（`@fastify/jwt`） | 登录后签发 JWT（7 天有效 + 静默刷新），无状态、支持多实例 |
| 数据同步 | 运动中定时增量上传 + 断网本地暂存补传 | 服务端按轨迹点序号幂等去重；失败进待同步队列自动重试 |
| 图表 | 自绘 Canvas（柱状图 + 折线图） | 统计趋势柱状图 + 详情页海拔/配速折线，不引入重量级图表库 |
| 图片导出 | Canvas 2D `canvasToTempFilePath` + 保存相册 | 注意相册授权 scope.writePhotosAlbum |
| 部署 | 云服务器 + Docker（仅后端容器） | Docker Compose 一键起后端，本地/线上环境一致；MongoDB 连现有实例 |
| AI 辅助 | **TDesign MCP Server** | 开发时用 AI 生成/校验 TDesign 组件代码（见第 6 节） |

## 5. 数据模型（草案）

```
User（用户）
├── _id            ObjectId
├── openid         string  微信 openid（唯一索引）
├── nickname       string  昵称（可修改）
├── avatarUrl      string  头像 URL（OSS）
├── gender         number  性别（可选）
├── settings       object  个人设置（单位制、默认运动类型、高精度定位开关）
├── createdAt      date
└── updatedAt      date

Activity（一次运动记录，云端）
├── _id            ObjectId
├── userId         ObjectId  所属用户（索引）
├── type           enum     hiking|walking|running|cycling|mountaineering|swimming
├── status         enum     in_progress | finished | synced   （进行中/已完成）
├── startTime / endTime   number 开始/结束时间戳
├── duration        number   时长（秒，扣除暂停）
├── distance        number   距离（米）
├── avgPace         number   平均配速（秒/公里）
├── calories        number   估算卡路里（kcal，按类型 MET 系数）
├── elevationGain   number   累计爬升（米，滤波后粗略值）
├── maxAltitude     number   最高海拔
├── startAddress / endAddress  string 起终点地址（逆地理编码）
├── trackPoints[]   TrackPoint  轨迹点数组（抽稀后）
├── markers[]       Marker      打点数组
├── lastPointSeq    number   已接收的最后一个轨迹点序号（幂等去重）
├── pausedMs        number   累计暂停时长
├── deviceInfo      object   记录设备信息（调试用）
├── createdAt / updatedAt

TrackPoint
├── seq            number   序号（客户端生成，幂等去重依据）
├── lat / lng       number   经纬度
├── altitude        number   海拔（高精度定位开启时有值，可 null）
├── speed           number   瞬时速度（可选）
└── timestamp       number   采点时间

Marker（打点）
├── id              string   客户端生成 ID
├── lat / lng       number
├── timestamp       number
├── type            enum     checkpoint | rest | photo | note
├── note            string   文字备注
├── photoUrl        string   照片 URL（OSS）
└── address         string   逆地理编码地址
```

**同步说明**：记录进行中，客户端按固定间隔将新增轨迹点（带 seq 序号）增量上报，服务端按 `lastPointSeq` 幂等去重；断网时数据进本地待同步队列，恢复后按序补传；结束后客户端调 `finish` 接口将 status 置为 finished。

## 6. TDesign MCP 说明（调研结论）

TDesign MCP 是腾讯官方维护的 **Model Context Protocol 工具服务**，用于在 AI 辅助编程中高效、准确地使用 TDesign 组件库。

**核心能力（工具）**
- `get-component-docs` — 获取组件文档，用于代码生成与转换
- `get-component-list` — 获取可用组件列表
- `get-component-changelog` — 组件变更日志
- `get-component-dom` — 组件 DOM 结构（自定义样式参考）
- `search-icons` — 图标搜索

**支持框架**：desktop（react/vue-next/vue）、mobile（mobile-react/mobile-vue/**miniprogram**/uniapp）

**接入方式**：在支持 MCP 协议的 AI IDE 中通过 JSON 配置，`npx -y tdesign-mcp-server@latest` 即可启用。

**本项目用途**：开发阶段让 AI 助手通过 MCP 获取 tdesign-miniprogram 准确组件 API、生成符合规范的页面代码、排查组件样式问题，减少试错。

**约束提醒**：MCP 只是开发辅助工具，小程序最终产物仍是 tdesign-miniprogram 组件库本身，需 npm 安装并按 tdesign-miniprogram 文档使用。

## 9. 风险与技术难点

| 风险 | 说明 | 应对 |
|---|---|---|
| 后台定位失效 | iOS 需"始终允许"，Android 厂商后台限制、省电策略杀进程 | 前台优先方案兜底；引导用户设置；`wx.onLocationChange` 后台降频 |
| 高精度定位权限 | `getLocation`/高精度模式需在公众平台申请"精确地理位置"接口权限，受类目审核影响 | 提前申请；审核不过则海拔降级为无（UI 隐藏海拔/爬升） |
| GPS 海拔精度 | 误差 ±10~30m，累计爬升积分放大误差 | 滑动平均 + 死区阈值滤波；UI 标注"仅供参考"；可开关关闭 |
| 轨迹漂移/精度 | 城市峡谷、室内 GPS 漂移 | 漂移过滤（速度/距离阈值）、暂停时可不采点 |
| 长轨迹性能 | 万级轨迹点导致 map 卡顿 | 抽稀算法、按缩放级别降采样 |
| 增量同步一致性 | 断网/崩溃导致本地与服务端点集不一致 | 序号幂等去重 + 待同步队列 + 结束后对账（以客户端 final 包为准） |
| OSS 密钥安全 | 前端直传若用固定密钥有泄露风险 | STS 临时凭证 + 最小权限 + 目录隔离（按 userId） |
| Canvas 导出兼容 | 不同机型导出样式不一致 | 真机矩阵测试；canvas 2D 接口统一 |
| 定位上报频率 | `wx.onLocationChange` 频率由系统决定 | 自行节流：距离/时间双阈值过滤 |
| 隐私合规 | 轨迹数据敏感（位置 + 时间可还原行踪） | 隐私政策、位置接口用途声明、用户可删除数据 |

## 11. 验收标准（MVP 定义）

一次完整的用户体验闭环：
1. 打开小程序 → 静默登录（无感）→ 首页选择运动类型 → 开始
2. 地图实时显示轨迹与数据（含海拔）→ 中途打点 1 次（含照片+备注）→ 暂停/继续 1 次 → 结束
3. 摘要页看到轨迹图与完整指标 → 保存（增量数据已同步后端）
4. 轨迹列表看到该记录 → 进入详情回看轨迹、打点与海拔曲线 → 轨迹回放
5. 详情页导出轨迹图 → 保存相册 / 生成分享海报 / 转发小程序卡片；导出 GPX
6. 统计页看到累计数据更新
7. 换设备登录同一账号，可看到历史轨迹
