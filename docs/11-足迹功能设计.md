# 11 足迹功能设计（Footprint Records）

> 2026-09-20 · 状态：设计已确认，待实现计划
> 范围：小程序新增「足迹」tab + 后端 `footprint-records` 模块。与现有运动轨迹点亮地图（packageFootprint / `GET /stats/footprint`）**完全独立、互不引用**。

## 1. 需求与决策记录

用户可创建"自己去过的地方"的足迹记录，字段：时间（年月日）、地点、人物、标题、描述、相关图片（最多 3 张，本地先压缩）。地点支持搜索与地图选点；因腾讯关键词搜索有额度限制，**主选点方式用 `wx.chooseLocation`（免费，自带搜索框+地图点选）**，另提供自建地图选点页作为补充入口。足迹地图用原生地图自带 marker 聚合簇展示密集区域，稀疏区域直接展示点，点击点弹出详情弹窗。

已确认决策：

| 决策点 | 结论 |
|---|---|
| 与点亮地图关系 | 完全独立，点亮地图仍从「我的」进入 |
| 可见性 | 仅自己可见，全部接口 `authenticate`，查询强制 `userId` 过滤 |
| 选点方式 | `wx.chooseLocation` 为主 + 自建地图选点页（关键词搜索走后端代理腾讯 place API） |
| 数据归属 | 独立 collection，不复用 activity marker（语义与生命周期不同） |

## 2. 数据结构

### 2.1 `FootprintRecord`（`src/models/footprint-record.model.ts`，collection `footprintrecords`）

```ts
const locationSchema = new Schema({
  name:     { type: String, default: '' },   // 地点名（POI 名或自填）
  address:  { type: String, default: '' },   // 详细地址
  province: { type: String, default: '' },   // 服务端由 region.ts locateRegion 离线补全
  city:     { type: String, default: '' },
  adcode:   { type: String, default: '' },
  latitude:  { type: Number, required: true },
  longitude: { type: Number, required: true },
}, { _id: false });

const footprintRecordSchema = new Schema({
  userId:      { type: Schema.Types.ObjectId, ref: 'User', required: true },
  visitDate:   { type: String, required: true },   // 'YYYY-MM-DD'，字符串免时区问题、可直接排序
  title:       { type: String, required: true, trim: true },
  people:      { type: [String], default: [] },
  description: { type: String, default: '' },
  location:    { type: locationSchema, required: true },
  photos:      { type: [String], default: [] },    // 裸 OSS URL，读时签名
}, { timestamps: true, versionKey: false });

footprintRecordSchema.index({ userId: 1, visitDate: -1 });
```

Zod 校验（`src/utils/validators.ts` 新增）：

- `visitDate`：`/^\d{4}-\d{2}-\d{2}$/`，不校验是否未来日期（允许记"计划去"）。
- `title` 1–50 字符；`description` ≤ 500；`people` 最多 10 个、每个 ≤ 20 字符；`photos` 最多 3 个 URL；`location.name` ≤ 100、`address` ≤ 200。
- 列表分页复用现有 `page/pageSize`（默认 20，max 100）。

### 2.2 图片存储

沿用现有 OSS 直传体系：`POST /oss/credential` 签发 `dir` 白名单正则已兼容 `footprints`（`/^[a-z0-9-]+$/`），key 前缀天然按用户隔离 `.../users/{userId}/footprints/`。DB 存 `cleanUrl` 后的裸 URL，响应时 `getSignedUrl(url, 86400)`。

## 3. 后端接口

路由文件 `src/routes/footprint-record.routes.ts`，注册前缀 `${apiPrefix}/footprint-records`（`src/app.ts`），服务层 `src/services/footprint-record.ts`，越权处理抄 `findOwnedActivity`（`findOne({_id, userId})` 找不到即 404）。响应包裹沿用 `{success, code, message, data}`。

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/footprint-records` | 创建。服务端补全 province/city/adcode（离线 `locateRegion`，不耗额度）。防刷：每用户 1h 最多 30 条，超限返回与 activities `assertCanCreate` 相同的状态码与文案风格 |
| GET | `/footprint-records` | 分页列表，`?page&pageSize&keyword`（keyword 对 title/description/location.name/address 做不区分大小写正则匹配），`visitDate` 倒序、同日按 `createdAt` 倒序；photos 签名 |
| GET | `/footprint-records/geo` | 地图专用全量轻量字段：`{id, title, visitDate, latitude, longitude, coverPhoto}`（coverPhoto=photos[0] 签名），不分页（私有数据、量级可控），按 visitDate 倒序 |
| GET | `/footprint-records/:id` | 详情，photos 签名 |
| PUT | `/footprint-records/:id` | 整体更新（含 photos 集合替换；差集部分服务端 `deleteOssObjects` 清理旧图） |
| DELETE | `/footprint-records/:id` | 删除记录并清理其全部 OSS 图片 |

选点辅助（放现有 geo 模块，`src/routes/geo.routes.ts`）：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/geo/search?keyword&latitude&longitude` | **新增**。后端代理腾讯 `place/v1/search`（region 优先按 keyword，location 就近）。唯一耗额度的接口：进程内缓存（keyword 归一化 key，TTL 1h，仿 `geo.ts` 现有缓存）+ 每用户限流（如 10 次/分钟）。返回精简 `{id, name, address, latitude, longitude}` 列表，max 20 |
| GET | `/geo/reverse` | **已存在**，自建选点页点选地图后回填地址，直接复用 |

错误语义：401 未登录；404 不存在/非本人；400 校验失败（ZodError 走现有 error-handler）；限流 429。

### 4.2 tab 主页 `pages/footprints/footprints`

- 顶部 segmented control：**地图 ⇄ 列表** 双形态，默认地图；右下角 FAB「＋」→ navigateTo 编辑页。
- **地图形态**：原生 `<map>`，数据来自 `GET /footprint-records/geo`。
  - marker 聚合（Task 5 修复轮定稿，官方 `component/map`「marker 聚合」+ `MapContext` 文档 + 模拟器实测）：**【本条与其下「实测修正的设计约束」条已于 2026-09-21 取代，见本节末「簇路线变更记录」】采用原生 `MapContext.initMarkerCluster` + `MapContext.addMarkers`（地图自带聚合簇）** —— `initMarkerCluster({enableDefaultStyle:true, zoomOnClick:true, gridSize:60, minClusterSize:2})`，密集点 marker 带 `joinCluster:true` 由地图渲染自带蓝底数字气泡；点簇原生放大展开，展开后的叶 marker 与稀疏孤点走 `bindmarkertap → openPopup`。契约不变：`markerId = records 下标 + 1`、`openPopup(record)`。
    实测修正的设计约束（**同样已于 2026-09-21 取代，见本节末「簇路线变更记录」**）：① 聚合要求 marker 命令式 `addMarkers` 注入，`<map>` 不再绑 `markers` 属性；② **`joinCluster:true` 的孤点也会被画成「1」字气泡**（与「稀疏区域直接展示点」不符），故 `joinCluster` 只给本地网格（`utils/footprint-geo.js#gridCluster`）判定为多点同处的点；③ 模拟器只回 `addMarkers` 的 `success`、不回 `onComplete`，`<map>` 的 `bindload` 不触发，注入时机挂在数据 setData 回调；④ 最大缩放仍并在一起的簇（同坐标点）走**成员列表半屏**兜底（`markerClusterCreate` 回灌成员表 + `markerClusterClick`，模拟器未派发过这两个事件，链路以真机回归为准）。
    历史结论留档：设计初稿写的声明式 `<map clusters>` / `bindclusterclick` / `bindclusteritemclick` 在微信文档中不存在（按其他家 SDK 形状写的）；初版曾降级为组件内网格聚合 + 离屏 canvas 自绘气泡，修复轮实测原生可渲染后已删除该降级实现。
  - 初始视野：`include-points` 实测形状是 `Array<{latitude, longitude}>`（文档无 `include-padding`，也没有 per-point padding），**没有 padding 可调** —— 点会正好贴边被裁一半，且单点包围盒零面积会把 scale 顶到 20（与 `components/track-map` 同一个坑）。故视野改为 `utils/footprint-geo.js#fitBounds` 自行算 `center` + `scale`（内边距 40/50/120，多点 scale 封顶 15、单点固定 12），纯函数已配 `test/footprint-geo.test.js` 单测。
- **列表形态**：分页 `GET /footprint-records`，卡片=缩略图(photos[0])+标题+日期+`location.city||name`，样式基准对齐轨迹页卡片；触底加载下一页。
- **详情弹窗**（地图/列表共用，自定义 overlay 组件，半屏底部弹出）：标题、日期、人物标签、描述、≤3 图横滑（签名 URL）、按钮「编辑」「删除」（删除需二次确认）。列表侧当前分页数据可直接提供弹窗内容；地图侧点 marker 时按 id 从已拉取的 geo 数据取，缺失字段（描述/人物）时请求 `GET /:id` 补齐。
- 空态：插画+文案「还没有足迹，点这里记录第一个去过的地方」。
- 加载/错误处理遵循既有规范：切换形态不闪屏、请求带序号守卫、失败可重试。

## 5. 安全与配额

- 所有 `footprint-records` 接口 `fastify.authenticate`；查询/变更一律带 `userId` 条件，越权返回 404。
- 腾讯 WebService 额度：本功能唯一新增消耗是 `/geo/search`（place API）。缓存在服务端进程内 + 每用户限流；`chooseLocation`、`/geo/reverse`（已有缓存）、省市补全（离线 region.ts）均不新增额度压力。
- 图片上传前后端双重校验（Zod max 3 + URL 前缀必须为本用户 OSS dir）；imgSecCheck 在客户端上传前执行，与服务端 OSS 10MB content-length 上限构成两道闸。
