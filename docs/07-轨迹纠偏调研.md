# 07-轨迹纠偏方案调研（M7）

> 调研时间：2026-08-12。目标：评估业界主流 GPS 轨迹纠偏方案，对照现有实现找增强点。

## 一、业界主流方案对比

| 方案 | 原理 | 成熟度 | 适用场景 | 备注 |
|---|---|---|---|---|
| **速度阈值过滤** | 按运动类型设最大速度，过滤突变点 | 通用基础 | 所有 | 掘金/超图通用方案；行人 >15m/s 过滤 |
| **距离跳跃检测** | 相邻点距离超历史均值 3σ → 漂移点 | 通用基础 | 所有 | 统计方法，可用 PostGIS 实现 |
| **Hampel 滤波器** | 窗口内 中位数 ± 3×MAD（中位绝对偏差）识别离群 | 鲁棒统计 | 所有 | 比固定倍数更鲁棒（无分布假设） |
| **卡尔曼滤波** | 状态预测+观测更新平滑 | 经典 | 平滑轨迹 | 阈值/噪声模型难调 |
| **滑动窗口统计（RCSWS）** | 范围约束 + 窗口统计修复异常 | 学术+落地 | GPS 清洗 | GPSClean 论文 |
| **趋势-残差双建模** | 样条拟合趋势 + 残差时间序列异常检测 | 学术 | 低采样轨迹 | 能识别不明显离群，复杂 |
| **百度鹰眼纠偏 API** | 去噪→抽稀→**绑路**→中断补偿 | 商业成熟 | 道路轨迹 | 需 App Key，支持步行/骑行/驾车策略 |
| **高德猎鹰纠偏 API** | denoise（去噪抽稀）+ **mapmatch（绑路）** + **threshold（精度过滤 ≥100m）** + 停留点漂移识别 | 商业成熟 | 道路轨迹 | 需 Key；精度过滤可直接借鉴 |
| **HMM/ST-Matching 地图匹配** | 隐马尔可夫模型匹配到 OSM 路网 | 学术+开源 | **道路**轨迹 | 需要路网数据；**非道路（公园/操场/山野）匹配差** |

## 二、与现有实现的对照

我们的 `cleanTrajectory`（后端）+ tracker（前端实时）已覆盖：
- ✅ 速度过滤（绝对 + 局部中位数自适应）——对应"速度阈值过滤"
- ✅ 距离/垂距离群（distLine + 局部尺度倍数）——对应"距离跳跃检测"
- ✅ 局部中位数自适应阈值——接近 Hampel 思路
- ✅ 首尾跳点（起点未收敛/结束漂移）
- ✅ 平滑（smoothTrackSmart 滑动平均 + 位移守卫）

## 三、可选增强点（按性价比排序）

1. **Hampel/MAD 替代固定倍数**：窗口内用 中位数 ± 3×MAD 判定离群，比"中位数×系数"更鲁棒（对速度/位移分布无假设）——改动小，值得做
2. **定位精度过滤**（高德 threshold 思路）：利用新增的 `accuracy` 字段，accuracy ≥100m 的点直接过滤——我们已有 60m 过滤（前端），后端可加一致性校验
3. **停留点漂移识别**（高德特性）：暂停/静止时 GPS 漂移聚类处理——我们已有"暂停不采点"（前端），基本覆盖
4. **卡尔曼平滑**：替代滑动平均，轨迹更顺——实现/调参成本中等，收益有限
5. **地图 API 绑路**（高德/百度）：仅对**道路轨迹**（骑行/驾车）有效；步行/跑步大量在非道路区域（公园/操场/山野），**绑路会画蛇添足**；且引入第三方依赖 + 坐标系（GCJ-02 兼容）+ 费用——**不建议**做
6. **HMM 地图匹配**：需要路网数据 + 对非道路场景差——**不适用**运动 App

## 四、结论

- 现有实现已对齐业界主流（速度 + 离群 + 自适应阈值 + 平滑）
- **建议只做 1（Hampel/MAD）** 作为最终增强，其余维持现状
- 商业地图 API 绑路（高德/百度）不适合运动轨迹（非道路场景为主），如未来做"骑行绑路到道路"再评估
