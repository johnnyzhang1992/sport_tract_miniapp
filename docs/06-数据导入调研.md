# 06-运动数据导入调研（M7 预研）

> 调研时间：2026-08-12。目标：确定数据导入功能的格式支持范围与实现方案。

## 一、热门运动 App 导出格式

| App | 导出途径 | 导出格式 | GPS 轨迹 | 备注 |
|---|---|---|---|---|
| **Strava** | 活动页导出 / 批量导出 | **FIT**（原始）、**TCX**、**GPX**、CSV | ✅ | 单条导出：FIT 为原始文件，TCX 含心率/功率，GPX 最通用 |
| **佳明 Garmin** | 手表/Connect | **FIT**（原生）、TCX、GPX | ✅ | FIT 是手表行业标准 |
| **高驰 COROS** | 手表/App | **FIT** | ✅ | 生态互转主要用 FIT |
| **华为运动健康** | 隐私中心数据副本（审核 7 天） | JSON/CSV（`motion path detail data.json`，含逐秒 GPS） | ✅ | 单条轨迹支持导出 **gpx/kml/tcx**；App 导入也支持这 3 种 |
| **小米/Zepp** | 官方批量导出 CSV（**无 GPS**）；App 单条导出 | **GPX**（单条）、CSV | ⚠️ 单条 GPX 有 | 官方批量数据无 GPS，价值低 |
| **Keep** | 官方导出 **Excel**（无轨迹） | Excel | ❌ | 官方无 GPS；模拟登录才能拿轨迹（非官方） |
| **悦跑圈** | 无官方导出 | — | — | 仅模拟登录（非官方） |
| **咕咚** | 无官方导出 | — | — | 仅模拟登录（非官方） |

**结论**：国内 Keep/悦跑圈/咕咚 **官方都不开放轨迹导出**（只有模拟登录，属灰色手段，不宜作为功能依据）。**真正可用的是**：
1. **GPX** —— 华为/小米/Strava 都能导出，最通用
2. **TCX** —— Strava/佳明/华为，含心率
3. **FIT** —— 佳明/高驰/Strava 原始格式，最完整但二进制
4. **华为 JSON 副本** —— 数据全（逐秒点），格式私有

## 二、格式对比（GPX / TCX / FIT）

| 格式 | 类型 | 制定方 | 数据完整度 | 解析难度 |
|---|---|---|---|---|
| GPX | XML 文本 | OGC 标准 | ⭐⭐⭐ 轨迹 + 时间/海拔（部分含心率扩展） | 低（fast-xml-parser） |
| TCX | XML 文本 | Garmin | ⭐⭐⭐⭐ + 心率/踏频/功率/圈 | 低（XML） |
| FIT | 二进制 | Garmin | ⭐⭐⭐⭐⭐ 全量 | 高（需专用解码库） |
| KML | XML | Google Earth | ⭐⭐ 仅轨迹 | 低（XML） |

## 三、建议方案（v1）

**格式优先级**：GPX（必做）→ TCX（必做）→ KML（可选）→ FIT（v2 可选）

- **后端**：
  - 新增 `src/services/import.ts`：解析 GPX/TCX（fast-xml-parser）→ 统一轨迹点（lat/lng/altitude/timestamp）→ 计算距离/时长/配速 → 创建 activity（status=finished）
  - 新接口 `POST /api/activities/import`（multipart 上传文件，≤2MB，校验：点数 ≥2、坐标合法、时间升序）
  - 防御：文件类型白名单（.gpx/.tcx/.kml）、XML 外部实体禁用、点数上限（如 5 万点）
- **前端**：
  - 「我的」页新增**数据导入**入口 → `wx.chooseMessageFile`（从聊天选择文件）→ 上传 → **预览确认**（运动类型/开始时间/距离/时长，可修正类型）→ 确认入库
  - 与"轨迹合集"联动：导入的轨迹自动出现在合集中
- **类型映射**：文件无运动类型（GPX 通常无）→ 默认「跑步」+ 用户确认时可选
- **测试**：GPX/TCX 样例解析单测（点数/坐标/时间/容错）

## 四、风险与注意
- FIT 解析需引入二进制解码库（如 fit-file-parser，纯 JS），体积/维护成本高 → v2
- 华为 JSON 副本格式私有且大 → 暂不支持，文档说明
- 导入数据内容安全：文件名/备注需过内容安全检测（与现有规则一致）
