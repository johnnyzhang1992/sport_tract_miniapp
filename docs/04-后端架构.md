## 1. 技术栈总览

| 层 | 选型 | 说明 |
|---|---|---|
| 运行时 | Node.js (LTS) | — |
| Web 框架 | **Fastify** | 性能好、原生 schema 校验（JSON Schema）、插件生态 |
| ODM | **Mongoose** | MongoDB 建模、索引、中间件 |
| 数据库 | **MongoDB** | 本地开发与线上已有实例，**直接新建独立库**（如 `sport-track`），不容器化 |
| 鉴权 | `@fastify/jwt` | JWT 签发/校验，7 天有效期 + refresh 机制 |
| 对象存储 | **阿里云 OSS** | STS 临时凭证（`@alicloud/sts-sdk`），前端直传 |
| 微信接口 | `axios` | 调 `jscode2session`（登录）、`getUnlimitedQRCode`（小程序码） |
| 部署 | Docker + Docker Compose | 仅后端容器；环境变量区分 dev/prod |
| 日志 | pino（Fastify 内置） | JSON 结构化日志 |
| 校验 | Fastify schema + `zod`（可选） | 请求参数强校验 |

## 3. 数据模型

> 与需求文档第 5 节一致，此处补充索引与关键约束。

### User
```js
{
  _id: ObjectId,
  openid: { type: String, unique: true, required: true },
  nickname: String,
  avatarUrl: String,          // OSS URL
  gender: Number,             // 0 未知 1 男 2 女
  settings: {
    unit: 'metric' | 'imperial',
    defaultType: 'walking',
    highAccuracy: true,       // 高精度定位开关
  },
  createdAt: Date,
  updatedAt: Date,
}
```

### Activity
```js
{
  _id: ObjectId,
  userId: ObjectId,                       // 索引（查询用户活动）
  type: String,                           // hiking|walking|running|cycling|mountaineering|swimming
  status: 'in_progress' | 'finished',
  startTime: Number,
  endTime: Number,
  duration: Number,                       // 秒（扣除暂停）
  distance: Number,                       // 米
  avgPace: Number,                        // 秒/公里
  calories: Number,
  elevationGain: Number,                  // 米（滤波后）
  maxAltitude: Number,
  startAddress: String,
  endAddress: String,
  trackPoints: [{
    seq: Number,                          // 客户端序号，幂等去重键
    lat: Number, lng: Number,
    altitude: Number | null,
    speed: Number,
    timestamp: Number,
  }],                                     // 索引：{ activityId: 1, 'trackPoints.seq': 1 }（复合唯一，可选）
  markers: [{
    id: String,                           // 客户端生成 ID
    lat: Number, lng: Number,
    timestamp: Number,
    type: 'checkpoint'|'rest'|'photo'|'note',
    note: String,
    photoUrl: String,
    address: String,
  }],
  lastPointSeq: Number,                   // 已接收最大 seq
  pausedMs: Number,
  deviceInfo: Object,
  createdAt: Date,
  updatedAt: Date,
}
```

**性能考虑**：长轨迹点较多，按 `seq` 追加用 `$push` + `$max lastPointSeq`；轨迹点数组上限（如 2 万点）保护，超出时服务端提示客户端抽稀。

## 4. API 接口清单

> 统一前缀 `/api`，除登录外均需 `Authorization: Bearer <JWT>`。

### 认证与用户
| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/auth/login` | `{ code }` → 后端调 `jscode2session` 换 openid → 查/建用户 → 签发 `{ accessToken, refreshToken, user }` |
| POST | `/api/auth/refresh` | `{ refreshToken }` → 新 accessToken（静默续期） |
| GET | `/api/users/me` | 当前用户资料 |
| PUT | `/api/users/me` | 更新昵称/头像 URL/性别/设置 |

### 运动记录（核心同步协议）
| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/activities` | 创建进行中活动，返回 `{ activityId }`（幂等：客户端可传本地 activityId 防重复创建） |
| POST | `/api/activities/:id/points` | **增量上传**：`{ points: [{seq,lat,lng,altitude,speed,timestamp}], fromSeq }` → 服务端按 seq > lastPointSeq 过滤追加，返回 `{ lastPointSeq }` |
| POST | `/api/activities/:id/markers` | 新增打点（含 photoUrl） |
| PUT | `/api/activities/:id/markers/:markerId` | 编辑打点（备注/类型/照片） |
| DELETE | `/api/activities/:id/markers/:markerId` | 删除打点 |
| PUT | `/api/activities/:id/finish` | 结束：提交最终数据包（完整点集/指标/起终点地址），服务端**对账**（以客户端 final 包为准补齐缺口，重算指标并校验），status → finished |
| PUT | `/api/activities/:id/cancel` | 放弃：status → cancelled（保留 7 天后可清理） |

### 查询与导出
| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/activities` | 列表：`?type=&month=&page=&pageSize=`，按 startTime 倒序 |
| GET | `/api/activities/:id` | 详情（含点集与打点） |
| DELETE | `/api/activities/:id` | 删除（软删除 or 硬删，含 OSS 文件清理） |
| GET | `/api/activities/:id/gpx` | 导出 GPX（含航点=markers），`Content-Type: application/gpx+xml` |
| GET | `/api/stats/overview` | 今日/本周/本月次数、距离、时长、爬升 |
| GET | `/api/stats/trend` | 近 7/30 天距离与时长（聚合） |

### 文件与分享
| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/oss/sts` | 签发 OSS STS 临时凭证（限定目录 `users/{userId}/...`、限定 action、短有效期） |
| POST | `/api/share/mini-code` | 生成小程序码（调 `wx.getUnlimitedQRCode`，scene 带 activityId，缓存于 OSS） |

## 5. 同步协议细节（核心）

**目标**：运动中定时增量上传 + 断网本地暂存补传（决策 D13），服务端幂等，最终一致。

```
客户端：
  1. 采点 → 本地缓冲（带 seq，全局自增）
  2. 每 30s（或缓冲 > N 条）：POST /points {fromSeq, points[]}
  3. 失败（网络）：入本地待同步队列（持久化），恢复后按序重试
  4. 结束：POST /finish 提交 final 包（完整点集 + 指标）
服务端：
  1. 接收 points：过滤 seq <= lastPointSeq 的重复点，$push 新点，$set lastPointSeq
  2. finish：以客户端 final 包为准 → 全量替换 trackPoints + 重算指标（防漏点/脏点）
  3. 对账响应：{ status, lastPointSeq, activity }
```

**冲突处理**：同一活动单设备记录，无多端并发写；`finish` 后禁止再传 points（返回 409）。

## 6. 安全与合规

| 项 | 方案 |
|---|---|
| 鉴权 | 所有业务接口 JWT 校验；`@fastify/jwt` + 路由级 `preHandler` |
| 数据隔离 | 所有查询强制带 `userId`（防越权）；对象 ID 校验 |
| OSS 安全 | STS 最小权限 + 目录隔离 `users/{userId}/` + 短时效（如 15 分钟） |
| 敏感字段 | openid 不出接口；日志脱敏 |
| HTTPS | 线上强制 HTTPS（Nginx 或云负载均衡终止 TLS） |
| 限流 | `@fastify/rate-limit`：登录/刷新限流，防爆破 |
| 隐私 | 轨迹数据属敏感个人信息：仅本人可查；删除接口同步清理 OSS 文件；提供账号注销（删除全部数据） |
| 微信侧 | 公众平台配置：合法域名（服务器域名 + 上传/下载域名 OSS）、申请"精确地理位置"等接口权限、隐私协议声明位置用途 |

## 7. 部署

### Docker Compose（仅后端容器）
```yaml
# docker-compose.yml
services:
  api:
    build: .
    ports: ["3000:3000"]
    environment:
      NODE_ENV: production
      MONGODB_URI: ${MONGODB_URI}        # 指向现有 MongoDB 实例（新建库）
      JWT_SECRET: ${JWT_SECRET}
      JWT_REFRESH_SECRET: ${JWT_REFRESH_SECRET}
      OSS_REGION / OSS_BUCKET / OSS_AK / OSS_SK / OSS_ROLE_ARN: ${...}
      WX_APPID / WX_SECRET: ${...}
    restart: unless-stopped
```

### 环境
| 环境 | MongoDB | 用途 |
|---|---|---|
| dev | 本地实例（`sport-track-dev` 库） | 开发联调 |
| prod | 线上实例（`sport-track` 库） | 生产 |

### 发布流程
1. `docker build` → 推送镜像仓库（或服务器直接 build）
2. 服务器拉取 → `docker compose up -d`
3. 健康检查 `GET /health`（MongoDB 连接状态）
4. 日志：`docker compose logs -f`
